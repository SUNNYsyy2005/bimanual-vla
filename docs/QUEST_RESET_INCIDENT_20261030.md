# VR 采集复位异常与离线修订（2026-10-30）

## 已知情况

用户在复位测试中反馈“动作大”“乱动”“速度快”。该次测试未成功完成，
最后报告 can0 在 0x155 发送失败并锁定连接。没有完整的逐周期发送／反馈轨迹，
不能据此认定 CAN 故障是异常运动的原因，也不能确认异常只发生在复位插值阶段。
测试进程已退出；本次修订之后没有再次启动真机运动测试。

代码检查发现原接管流程存在风险：使能／切换到 100% 固件速度发生在保持目标发送前，
可能暴露固件旧目标；使能前捕获的位置也可能已失效。这是已发现的风险路径，
尚不是本次异常运动的确定根因。

## 当前修订

- VR 接管和复位不再自动使能或切换模式。必须已有新鲜、健康、已使能的
  CAN/MOVE_J 状态；复位先检查双臂，再发送任何保持目标。重启后的设备可能因此拒绝接管。
- 复位以新鲜实测位置开始，保留夹爪目标，停稳后执行双臂同持续时间的关节五次插值。
  目标速度上限为 0.10 rad/s（约 5.7°/s），加速度上限为 0.30 rad/s²。
- 每周期检查目标步长；运动或到位阶段实测速度超过 0.30 rad/s、运动跟踪偏差
  超过 0.05 rad、线程周期超过 0.15 s 时中止。双臂新目标全部检查成功才更新。
- 路径检查后及逐臂发送前检查停止／急停请求，防止检查期间的停止请求被遗漏。
- 异常退出仅在反馈健康时尝试实测位置保持；显式急停走既有急停路径。
  软件中止或发送保持不等于已验证物理制动成功，CAN 故障时也不能保证命令送达。
- 已有驱动限位和自碰撞检查保留；它们不包含桌面、外部物体或双臂互碰检查。

手柄 A 的目标仍为连接时姿态；GUI 的目标仍为与推理共享的保存姿态。
目前保存文件的双臂 J2 约为 −0.0335 rad，低于当前驱动下限 0，复位会拒绝。
未覆盖或静默裁剪该文件，应在确认机械臂姿态合适后显式重新保存。
