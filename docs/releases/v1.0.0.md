# v1.0.0 — First Stable Release

Release date: November 6, 2026.

This release brings Piper collection, policy deployment, human intervention,
and RECAP into one GUI/CLI workflow.

## Supported workflows

- **Joint-angle control:** joint-space policy targets, replay, and single-arm or
  bimanual execution with driver-limit and feedback checks.
- **End-effector pose control:** the canonical `delivery` contract, local IK,
  RTC action chunks, and Ruckig execution. EEF chunk smoothing and gated
  still-phase smoothing address the previously observed trajectory jitter.
- **Two teleoperation methods:** master/slave Piper arms and Quest VR, with
  synchronized multi-camera recording and gripper control.
- **Human takeover:** switch between policy execution and Quest control,
  synchronize ownership with the GUI, and use multiple clutch segments during
  an intervention. Invalid waiting and handoff frames do not become policy
  training samples, and action chunks cannot cross segment boundaries.
- **RECAP:** save success/failure/abort outcomes after stopping inference;
  retain raw rollouts and intervention annotations; export valid policy and
  human segments to LeRobot; reuse RLinf returns, value-model training, and
  advantage labeling with the existing OpenPI/JAX policy training adapter.
- **Shared hardware configuration:** maintain left/right arm identities,
  CAN selectors, RGB camera mappings, and Quest settings through the GUI.

## Real-robot validation

The robot operator confirmed on November 6, 2026 that both joint-angle and
end-effector pose policy execution have completed real-robot tests and the
previously observed execution jitter is resolved in the tested configuration.
This is the hardware validation basis for the release statement; software tests
alone are not presented as evidence of physical robot behavior.

RECAP training integration is available. This release does not report a new
end-to-end RECAP training result or a measured policy success-rate improvement.
The separate [Full EEF compatibility bridge](../deployment/FULL_EEF_COMPAT.md)
retains its own representation/kinematics validation scope; the core control
test result does not imply that every imported checkpoint has been motion-tested.

Release software checks passed: 382 tests and 77 subtests covering deployment,
joint and pose trajectories, hardware admission, the EEF compatibility bridge,
VR input/control, RECAP recording/export/training adapters, and Dashboard RECAP
request validation. Python syntax, shell syntax, and documentation links were
also checked. These checks did not command physical hardware.

## Known initialization issue

After joint-zero recalibration, an enable-time measured-pose hold deviation was
observed on November 6, 2026. The affected attempt was stopped, and no new saved
home pose was written. That initialization behavior remains under investigation;
the policy-execution jitter result above does not establish that post-calibration
startup recovery has been resolved. Driver limits and motion-stop checks remain
in force.
