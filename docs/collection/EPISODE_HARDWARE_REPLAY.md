# Episode 真机回放

采集页面选中 episode，点击 **Replay episode** 打开配置窗口。**Video preview**
只播放记录图像；文件列表双击也只预览。只有点击 **Start hardware replay** 才启动真机流程。

仅支持当前采集器生成的 v3 NPZ，使用记录的测量姿态和对应时间戳回放，
不把训练用 actions/chunk 当作控制命令。删除末尾一帧采集器添加的终端填充；
记录的夹爪开度比例按数据契约的 0.07 m 范围转换为控制单位米，不使用硬件行程重新解释比例。
旧数据格式、缺少元数据、未知单位、非 slave_base 坐标以及非法数值直接拒绝。

## 操作流程

1. 选择文件及 `joint` 或 `eef` 表示。窗口根据文件实际包含的数据提供选项；
   joint 文件没有记录末端位姿时不会补算该表示。双格式文件支持切换，默认选择已完成真机验证的 joint 模式。
   左单臂、右单臂、双臂由 episode 元数据确定，双臂顺序固定为左、右。
2. 设备沿用采集 GUI 的对应 CAN 设置。GUI 默认勾选 **Enable motors while holding current pose**：
   允许从正常、六电机均未使能的待机状态准备回放。取消勾选则要求已使能且处于 CAN 关节模式。
   使能开关不会解除急停；部分电机使能状态拒绝自动处理。启动前故障恢复由独立开关控制，见下文。
3. 确保主臂控制已隔离、没有其他控制程序，并清空首帧移动及后续整条轨迹的运动范围；
   确认窗口中的独占控制选项。主从仍共线并跟随时不能执行真机回放。
   不需要独占控制即可视频预览。
4. 点击开始后在独立进程中只读连接，最多等待 3 秒收齐状态、关节、夹爪和六个电机反馈，
   再检查静止状态、外部控制报文，并查询驱动限位。每次重试使用新进程，避免 SDK 的
   接口单例缓存和采集预览共享连接。等待仅用于首批反馈；只有下文列出的启动故障允许清除一次。
   记录的关节路径越限或末端数值不合法时，在任何运动命令前拒绝。
   当前实测 J2 若仅略低于下限（最多 0.06 rad，沿用推理侧的测量容差），使能准备会显式记录
   `aligning_start_boundary`，先以 1% 速度移动到查询到的 J2 下限。原始实测值保留，
   下发目标均在原驱动/软件限位内；不会修改驱动限位、零位或数据。其他关节越限及更大的 J2
   越限仍拒绝。取消使能准备也会拒绝越限起点。
   若启用使能准备，检查通过后先预载六关节目标（正常为实测姿态，边界准备时仅 J2
   使用合法下限），等待至少 0.3 秒，随后逐个请求 1～6 号关节使能，避开全电机使能；
   此阶段监测夹爪开度，但不发送夹爪命令。
   最多等待 3 秒确认使能；需要 J2 边界移动时总准备时间最多 10 秒，并在边界到位稳定
   0.3 秒后继续。以三次更新的反馈确认使能和 CAN 关节模式。
   目标保持阶段关节漂移超过 0.01 rad 或夹爪漂移超过 2 mm、反馈过期、出现故障或外部控制即停止。
   边界移动的 J2 在实测起点与边界之间运动，其余关节沿用同一漂移保护。
   双臂确认准备完成后才进入首帧移动。
5. **自动以低速 Ruckig 轨迹移动到首帧关节角和夹爪开度。** 此阶段固定平滑，
   默认关节速度不超过 0.08 rad/s，独立超时 120 秒；不调用固件回零接口。
   到位并稳定至少 0.3 秒后，重新读取反馈；EEF 模式还核对首帧末端姿态。
6. 然后从第 0 帧启动 episode 时钟，按所选速度回放。默认 0.25 倍速。
   默认回放限制与推理共用定义，并从当前推理面板复制有效配置；末帧到位等待最多 30 秒。
   最后等待实测姿态到位稳定，不自动回零或回起点。

## 与推理对齐的配置

打开回放窗口时读取推理面板当前配置，包括关节平滑开关、目标更新频率、下发频率、
关节速度/加速度/jerk 上限，以及末端平滑开关和全部末端平滑参数。
这些值是打开窗口时的快照，可在回放窗口单独调整；修改推理参数后重新打开回放窗口以重新读取。

两层频率分别对应推理的 `--control-hz` 和 `--servo-hz`：例如模型每个 chunk 步为
30 Hz、joint smoothing 为 100 Hz 时，回放每 1/30 秒更新录制目标，
每 1/100 秒推进关节平滑、检查反馈并发布关节命令。EEF 平滑和 IK 在目标更新频率运行。
两侧关节、夹爪及 episode 时间使用同一回放时间轴。频率变高不会改变请求的 episode 播放倍率。
推理关闭关节平滑时，其实际下发频率等于目标更新频率，回放也按该状态初始化。
Legacy 推理平滑后端不支持自动映射，窗口会明确报错，避免默默替换为另一算法。

基础限制来源于 `bimanual_vla/deployment/execution_defaults.py`，推理与回放共同引用：

| 参数 | 共用基础值 |
| --- | ---: |
| 固件速度百分比 | 推理 100%；独立 CLI 回放默认 10% |
| 关节速度上限 | 1.20 rad/s |
| 关节加速度上限 | 8.0 rad/s² |
| 关节 jerk 上限 | 60 rad/s³ |
| 关节跟踪误差门限 | 0.35 rad |
| 夹爪速度上限 | 0.08 m/s |
| 反馈最大年龄 | 0.5 s |

GUI 优先使用当前推理面板中已启用参数的实际值（如自定义 jerk），而非强制覆盖为基础值。
在回放窗口中开启 Joint smoothing 时，会恢复推理面板的 servo 下发频率（通常 100 Hz）；
关闭时恢复目标更新频率（例如 30 Hz）。切换不改变 `control_hz`。
实际关节速度还取软件上限与驱动查询上限乘固件速度百分比的较小值，并对后者保留 20% 跟踪余量。
例如查询上限 3 rad/s、固件速度 100%、软件上限 1.2 rad/s 时，有效参考上限为 1.2 rad/s。
此协调策略由回放和推理共同使用，避免参考生成速度持续超过固件响应；它不证明原录制轨迹能以原速复现。
日志 `limits_verified` 同时保存请求速度、固件百分比和最终参考上限。
CLI 没有推理面板，默认沿用推理 CLI 的基础频率：目标 20 Hz、下发 100 Hz；
可显式指定 `--control-hz 30 --servo-hz 100` 对齐当前 30 Hz 模型。
首帧接近仍使用独立的低速上限 0.08 rad/s，J2 边界准备仍为固件 1%。

两条路径都在关节空间下发到 PiPER：EEF 模式先处理记录的基座系位置与旋转，
经已有连续 IK 求得局部关节解，再交给关节写入路径。双臂目标均计算和检查通过后才开始下发。
EEF 回放不使用旧推理任务的 XYZ 盒形范围。当前使用的官方 PiPER SDK 的 `EndPoseCtrl`
没有定义这组范围，它也不能代表左右臂的实际可达空间。记录与平滑后的 XYZ 仍检查有限数值，
可达性由 IK 检查，解出的关节仍受实际驱动/软件关节限位约束。
EEF 回放每个控制周期都使用与推理相同的在线链路：当前反馈、可选 PoseTrajectory、连续 IK、
同一组 IK 搜索半径/正则项/位置旋转门限，以及同一 warm start 分支。开启 Joint smoothing
时使用完整 IK 解交给 Ruckig；关闭时使用推理的 `ik_max_joint_step_rad` 单步限制。
EEF 平滑只约束末端平移和旋转，不能保证 IK 后的关节速度；IK 单步限制只作用于当前命令，
不暂停或重排 episode 时间轴。不会做整段预规划、运行中回退目标或专用的另一套 EEF 控制器。
日志 `ik_rate_limit` 保存当前周期的 IK 限制结果。
加速度与 jerk 连续性仍需启用关节平滑，反馈过期、跟踪超限和不可达仍会停止。
关节角模式关闭关节平滑时，仍拒绝超过速度限制的原始目标，并报告关节及所需速度。
连续 IK 的关节接近偏好为软约束；若它使求解结果超过末端位置/旋转误差门限，
在相同局部关节搜索范围内只做一次去除该偏好的精化求解。位置、旋转和关节门限保持原值，
精化后仍不满足就停止；不会为了继续回放放宽可达性检查。该求解器也由推理共用。
这里没有碰撞规划器；关节限位和跟踪检查不能证明路径无碰撞。

## 自动恢复

GUI 默认勾选 **Automatically clear eligible cooled, disabled driver faults once before replay**。
CLI 默认启用，可用 `--no-auto-recover` 关闭；配置字段为 `auto_recover`。
此开关仅处理启动前的驱动故障，不控制已有的正常待机使能选项。

| 状态 | 自动处理 |
| --- | --- |
| 首次连接反馈未收齐 | 最多等待配置的 3 秒；不发送运动命令 |
| 正常待机、六关节均未使能 | 勾选保持姿态使能后按已有流程逐关节使能 |
| 已冷却但仍锁存的过热故障 | 满足以下条件后，每个关节只清除一次 |
| 软件/硬件急停、碰撞、堵转、欠压、过流、未知故障 | 拒绝自动清除或重启，给出原因 |
| 运动中反馈过期、跟踪超限、控制时钟停滞 | 停止，不自动续播或重复动作 |

故障白名单沿用部署模块 `hardware_safety.recover_return_faults` 的本地策略：原始驱动状态
仅允许 `0x02` 或 `0x22`，电机和驱动温度均为 0～45°C，故障关节及双臂所有关节均未使能，
六关节反馈完整且新鲜，机械臂总体状态正常且 `err_code=0`，主臂控制已隔离。
45°C 是保守的恢复门限，不代表厂家额定温度。

先观察静止 1 秒，关节漂移不得超过 0.003 rad、夹爪不得超过 1 mm；清除前再次检查。
只发送对应单个关节的 `JointConfig(clear_err=0xAE)`，`set_zero=0`、加速度配置不生效。
清除后再观察 1 秒，必须获得健康、静止反馈后才能继续预检和使能。
故障未消失、复发、出现新故障、反馈不完整或收到停止请求时立即退出，不循环清故障。
恢复日志包含检查、静止等待、具体关节清除以及结果。

不发送 `EmergencyStop(0x02)` 或 `ResetPiper()`：当前 SDK 二者的报文相同，可能使机械臂掉电。
设备已经进入急停时不能靠这个开关自动解除。

## 平滑选项

| 选项 | 关节回放 | 末端位姿回放 |
|---|---|---|
| Joint smoothing | 可选 Ruckig，限制关节速度/加速度/jerk | IK 后的关节轨迹平滑，独立可选 |
| End-effector smoothing | 不生效 | 可选已有 PoseTrajectory，限制平移/转动速度及加速度 |

EEF 模式可独立开关两个平滑阶段；两项都关闭即直接播放检查通过的 IK 目标。
旋转平滑使用 SO(3) 最短路径，不对欧拉角做线性插值。
开启任一对应平滑阶段时夹爪也按速度限制渐变。
平滑后的下发轨迹可能滞后于记录轨迹。程序 `completed` 仅表示完成回放流程并达到末帧，
不代表原轨迹的逐帧位置、时间和任务结果已复现；须同时评估记录目标→下发目标及下发目标→反馈两类误差。
关闭平滑保留速度、限位和反馈检查；目标跳变过大时拒绝，提示降低回放速度或启用平滑。
降低时间倍率不会消除记录中单帧跳变，因此有些数据在关闭平滑时仍无法回放。

关节速度/加速度/jerk、夹爪速度、跟踪误差、首帧移动速度/超时以及末端平滑参数可在窗口设置。
平滑可能引入延迟；结束时额外等待最终姿态收敛，超时则停止，不把“已发完命令”当成成功。

## 停止与互斥

**Stop replay**、关闭运行中的回放窗口、退出采集 GUI 时会请求停止。
默认采用**停止并保持使能**：停止推进 episode，对本次回放已控制、反馈新鲜且健康、
仍处于已使能 CAN 关节模式的机械臂，将当前实测关节角写为位置保持目标。
不改夹爪目标，不自动回起点，不发送失能、待机切换、软件急停或恢复命令。
IK 求解失败等软件异常也走同一保持路径，避免普通退出触发掉电。
反馈过期、驱动故障、部分失能、控制权变化或实测关节越界时，不发送新的保持目标，
也不自动使能/复位；保留固件原状态，日志和 GUI 明确提示保持未确认。
此时软件无法保证停止或维持扭矩，须现场处理；硬件急停仍是独立的紧急操作。
未参与控制的机械臂不接收任何停止命令。
断开 SDK 通信本身不发送失能；电机故障、设备断电或固件自身保护不受本功能控制。

回放期间不能开始采集、推理、姿态回位、CAN 重配或设备连接/断开；
已有纯监听预览可继续。回放实例按实际 CAN 接口互斥。
SocketCAN 监测持续拒绝非本机来源的主臂控制帧，包括静止时的低频控制；
它不是硬件仲裁，也不能排除其他本机进程，所以独占控制确认不能省略。

GUI 日志保存在 `~/.local/state/bimanual-vla/replays/`，包括文件、CAN 选择器、参数、
首帧移动/回放阶段、采样的实际下发目标及反馈、完成/失败状态。
回放采样还保存 `recorded_targets` 和 `recorded_representation`，用于区分轨迹平滑滞后与硬件跟踪误差。
同目录的 `.config.json` 保存该次子进程的完整配置；失败日志保留子进程异常堆栈。
不保存管理员密码或其他凭据。

若显示 `motors disabled at joints [...]`，代表已收到完整电机反馈，但列出的关节未使能；
这不同于 CAN 未连接。隔离主臂控制后，可勾选保持当前姿态使能的选项，再点击开始。
若显示 `measured starting joints outside limits`，会列出关节、实测角度和允许范围；
除上述小范围 J2 起点准备外，必须先按设备操作流程调整到限位范围内，
不会裁剪实测姿态或放宽限位来使能。
若显示 `No complete fresh CAN feedback within 3.0s`，检查设备供电、接口绑定及 CAN 实时报文。
首批六电机消息分批到达属于正常启动过程：`received` 部分为 false 时应继续等待，
只有达到等待期限仍未收齐才报超时。CLI/GUI 子进程与恢复模块共用 `replay_errors.py`
中的异常类型，避免 `python -m` 启动时重复模块身份导致等待异常未被捕获。

## CLI

在机器人 Conda 环境运行。默认仅检查文件信息，不连接 CAN：

```bash
python -m bimanual_vla.collection.replay path/to/ep_0000.npz
```

明确启用执行、隔离主臂并已建立独占控制之后，才使用以下执行参数。
请用采集 GUI 中的稳定 CAN 选择器替换示例接口：

```bash
python -m bimanual_vla.collection.replay path/to/ep_0000.npz \
  --mode eef --speed 0.25 --left-can can0 --right-can can1 \
  --joint-smoothing --no-eef-smoothing --enable-before-replay --allow-execution --exclusive-control
```

本功能的软件测试使用模拟设备；测试通过不代表当前接线可以执行，也不代表已完成真机动态验证。
CLI 默认不自动使能；`--enable-before-replay` 显式开启以上准备流程。
