# 切换本地 IK 与松灵原生 EEF 控制

两种方式适用于 EEF/delivery 策略；默认仍为 `local_ik_joint`。

| 选择 | 策略执行路径 | 速度约束 |
| --- | --- | --- |
| `local_ik_joint` | 本地数值 IK → Ruckig → SDK `JointCtrl` | 本地关节规划限制及驱动限制 |
| `piper_eef` | SDK `MotionCtrl_2(1,0,speed_pct,0)` → `EndPoseCtrl` | 固件 MOVE P 规划、`--speed-pct` 及驱动限制 |

原生模式的 IK 在机械臂固件中运行，不启动本地 IK 工作进程，不使用关节 Ruckig
生成策略动作。`--trajectory-max-speed-rad-s` 等关节规划参数仍可用于启动/归位，
但**不约束原生 EEF 策略运动**。固件选取的中间关节路径不能由主机反馈检查提前证明。
本次没有新增碰撞规划或自动失能逻辑。

## GUI

重新打开 GUI，在 **Action continuity settings → EEF control** 下选择：

- `local_ik_joint`：现有本地 IK 方式。
- `piper_eef`：松灵固件原生 EEF 方式。

客户端运行期间禁止切换，先 Stop，等进程结束后再选择并启动。原生模式下关节规划
页禁用，避免把关节 Ruckig 参数误认为原生控制参数。数据集硬件回放仍使用本地 IK，
不会随该选项暗中切换；选择原生模式时回放入口会提示先切回本地模式。

**End-effector reference → EEF target smoothing (host)** 是主机位姿参考平滑，
不是松灵固件的“内部 IK 平滑”开关。两种模式分别保存启用状态和各项参数；旧设置
只迁移到本地模式，原生模式初始关闭。

遵循连续 RTC 跟踪约定：**开启 RTC 时，正常执行旁路逐点停车式 EEF 平滑**。
若要对照原生 EEF 的主机平滑开/关，先关闭 Model-side RTC。日志与每臂诊断记录
旁路原因；本地 IK 在退出旧 RTC 执行后的缩步恢复仍可使用该平滑器。

## CLI

在原有启动命令中增加以下之一，其余设备、策略、相机参数保留：

```bash
--eef-control-mode local_ik_joint --no-pose-trajectory
```

```bash
--eef-control-mode piper_eef --no-pose-trajectory
```

原生模式下对照主机平滑（同一次对照均关闭 RTC）：

```bash
--eef-control-mode piper_eef --no-rtc-enabled --pose-trajectory
```

关闭平滑则替换为 `--no-pose-trajectory`。与已有同名参数合并，避免同一命令同时
保留相反开关。原生模式选择 joint 策略会明确报错，不自动回退成本地 IK。
policy 服务端无需修改。停止并重新启动客户端后加载新控制方式。

## 模式交接、停止与恢复

启动姿态仍通过现有受保护的关节路径到达。仅 `piper_eef` 在查询到的驱动限位
内侧留出 1° 启动余量，修正贴边关节；例如 J2 下限 0° 时启动目标至少为 1°，
J3 上限 0° 时启动目标至多为 -1°。这不改变驱动硬限位、运行时模型目标或保存的
归位配置文件。本地 IK 模式仍使用原有启动裁剪方式。

原生启动实测到位容差不超过 0.1°，停稳后再次确认到位及至少 0.5° 限位余量。
关节写入器退出后，原生写入器在发送任何 MOVE P 指令前再次检查双臂余量，
再以实测 EEF 位姿保持，等待**请求之后的新鲜状态反馈**确认 CAN/MOVE P。
模式确认还不代表首个 EEF 保持被固件接受：启动函数必须继续确认稳定保持，
才报告 Native EEF active 并要求新观测推理。延迟返回的固件拒绝仍按启动失败处理。

切回启动关节模式时，启用握手只用请求之后的新状态确认 MOVE_J。缓存中早于
请求的 MOVE_P 目标超限帧不代表新关节保持失败；在保持目标位于驱动范围内时
允许有界等待新帧。新反馈仍超限或出现驱动/其它故障则停止，不自动清错。

原生写入器独立于推理线程，以控制频率发布，验证双臂目标后才发送。XYZ 使用
0.001 mm（米乘 1e6），XYZ Euler 角使用 0.001 度。正常运动保持模型时间轴，
不根据夹爪变化逐点停车；工作空间、数值、夹爪范围及局部位姿步长检查保留。

反馈线程检查 CAN、反馈新鲜度、驱动使能/状态、模式及实测关节限位。实测关节
沿用已有反馈校准容差；不修改驱动硬限位，也不在主机伪造 native IK 成功结果。
持续策略跟踪失配沿用连续跟踪保护。参考超时或队列耗尽时，写入器捕获实测位姿
作为固定保持目标，并使旧 RTC 执行失效。停稳后仅允许新观测重新开始。

Stop 请求实测位姿保持，并在新反馈中检查：固件报告到位、关节变化速度低于
.01 rad/s、EEF 平移/旋转变化速度低于 .002 m/s / .02 rad/s、保持位置/姿态误差
小于 .005 m / .05 rad，连续稳定 .2 s。默认最多等待 3 s。冻结时间戳、错误状态
或停稳超时不能授权自动归位。这里是观测到的停稳检查，不是固件制动能力认证。
启动及运行时保持也有 3 s 停稳截止时间，超时锁定为原生控制故障。

确认停稳且原生线程退出后，归位先重新确认 CAN/MOVE J 实测关节保持，再交给
现有归位流程。两种活动写入器不能重叠。故障会锁住原生写入器，禁止自动失能或
隐式恢复。GUI 关闭沿用既有自有进程清理和超时升级流程。

## 诊断与验证范围

- `eef_control_mode` 标记所选方式，`ik_execution.backend=piper_firmware` 标记原生 IK。
- `native_eef` 记录模式、发布次数、hold 原因、执行 epoch、实测误差、停稳与故障。
- 固件拒绝与反馈过期分别报告。故障中保存交接/运行阶段、状态字、反馈年龄、实测关节、驱动限位、实测 EEF 和最近发送的 EEF 整数值。
- SDK 状态 `arm_status=4` 为目标关节角度超限，`2` 为无解，`3` 为奇异点；`err_code=0` 不代表 `arm_status=4` 可以忽略。
- 每臂 `control_path=piper_native_eef`、`piper_endposectrl_units` 记录实际接口及单位。
- 原生路径的 `commanded_joints_rad` / `full_ik_solution_joints_rad` 为 null。

离线测试使用内存假传输，覆盖单位/旋转、模式确认失败、双臂校验、看门狗、反馈
失效、Stop/线程退出、归位交接、RTC 屏障、两种平滑设置和 GUI 配置隔离。
未连接 CAN，未进行实机运动测试；机械臂固件的实际轨迹与停止行为尚未验证。
