# 16:56:28 实测及实际时钟交接修改

运行：`20261021T165628.103059+0800_139734`，8099，44.64 秒。
记录明确包含 `handoff_mode=ready_then_splice`，已加载本次交接修改。
RTC delay=7、horizon=10，推理频率配置 2 Hz，关节限制仍为 0.6 rad/s、3 rad/s²、60 rad/s³。

## 修改

- 删除依赖历史耗时的 `_chunk_prepare_lead_s`，完整规划在发布锁之外完成。
- 完成后按实际时钟及尚未到期的 RTC 承诺选择交接点。
- 在一个发布周期之后的可用时刻，从旧轨迹的 q/v/a 生成经 Ruckig 完整极值检查的局部过渡，接入新轨迹同一绝对时间轴上的 q/v/a。
- 不把旧的预测计划起始状态提前发布，也不平移模型的目标时间轴。保留已承诺的旧前缀及其来源标签。
- 局部过渡计算赶不上发布时钟时，只重算局部过渡，最多三次；保留旧计划并报告延期，避免增加等待预算。
- 完整规划批量求值插值曲线，复用已求解并检查的 Ruckig 轨迹采样，避免再为每组状态重复求解。
- 所有规划计算均在 100 Hz 发布线程以外；提交时检查暂停、故障、版本变化、新增 RTC 承诺及截止时刻。

这仍不是零延迟：局部过渡需要计算，100 Hz 发布存在时钟量化，未到期的 RTC 前缀仍须履行。
桥接开始后即可改变规划加速度；桥接终点不代表机器人等待至该时刻才接纳新轨迹。

## 尚存问题

- 本轮没有 RTC 前缀不一致导致的推理结果拒绝；只有两次启动稳定前的结果拒绝。
- 第 54 代完整规划发生一次 Ruckig 同步求解失败，候选被拒绝。
- 随后一次跟踪保护检测到连续三个周期超过 0.1 rad，清空队列并保持。
- 第 67–74、76 代共九个候选含左关节 2 越界目标（约 -0.100～-0.107 rad），触发整段候选拒绝，主要集中在运行第 35～40 秒。
