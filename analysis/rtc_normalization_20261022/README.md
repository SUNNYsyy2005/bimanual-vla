## 归一化粒度：没有发现轴混用，确有尺度问题需要验证

1. **动作 Normalize**：state/actions 分开，各 14 维。每关节独立 q01/q99，所有 50 个时间步共用该关节的统计；`RunningStats.update` 把 batch 和时间维展平，仅保留最后一维。不是每个请求/前缀重新计算统计，也不是把左右臂/所有关节合用一个标量。
2. **原点**：训练和推理先把关节绝对目标减去当前 chunk 观测关节，再归一化；两夹爪保持绝对 opening fraction。客户端规划前缀在服务器按新观测重新编码；其物理含义不是相邻点位移。
3. **填充**：14 维归一化完成后补到 32 维。当前服务器已有 clean-prefix padding 修复，前缀的后 18 维归零。此问题历史上存在，但不能当作本次新发现或当前未修复问题。
4. **RMSNorm/adaRMSNorm**：在每个 token 的隐藏通道维求均方，未跨 chunk 时间维归一化。RTC 的 flow time conditioning 是 B×T×D，前缀 time=0、后缀 time=t；它是去噪时间条件，不是物理时间或关节速度。
5. **状态分箱**：π0.5 默认把归一化后的实测 state 转为 256 档文本输入；这确实存在离散粒度，区别于连续动作 Normalize。右 J2 每档约 0.008835 rad（0.506°），左 J2 约 0.008184 rad，左右 J1 约 0.0134–0.0135 rad。当前记录在同一状态档内和跨档时都能出现回退，没有证据把跨档单独确定为原因；图像和连续前缀也仍在提供信息。

### 数值验证

`audit_cpu.py` 导入当前远程生产 transforms、RTC reanchor 和模型 RMSNorm，只在 CPU 上使用录制样本与小张量：

- 相同动作分别按 6/7/8/10/50 步编码，相对于整段编码后截取，最大差 **0**。
- RTC 重编码与训练动作编码差异最大约 **3e-8**（float32 转换）；物理动作往返最大约 **1.02e-7**，6/7/8/10 点约 **2.84e-8**。
- 修改其他时间步的动作，不影响当前步的编码；前缀填充维保持 0。
- stock RMSNorm 与服务器扩展版，在输入/参数 float32、BF16 的四组组合下，同条件广播结果最大差 **0**。
- 把其他 token 的输入与 conditioning 大幅改变，当前 token 的 RMSNorm 输出差 **0**。

这排除了所测实现中的“六步/八步前缀各自重新归一化”“时间维混入 RMSNorm”“补齐维参与物理动作统计”等解释。CPU 小张量测试不等于完整模型所有精度行为的验证，也不证明训练历史上的所有代码版本相同。

### 归一化范围的准确解释

当前真实关节的 1 个 normalized unit 对应 **0.129–0.934 rad**。右 J2 为 **0.9055 rad**，因此 normalized error=0.01 对应 0.00905 rad；0.02 rad 回退约为 0.0221 normalized unit。这个尺度会影响损失对细小物理误差的权重，但它不会凭空改变相邻差分的符号。

文档“0.004 rad 不到范围的 1%”不能对所有关节一概而论：0.004/0.129 约 3.1%，0.004/0.934 约 0.43%。平均单步位移和各关节范围也不是同一个分布统计。远期累计位移扩大 chunk-origin 范围的解释合理，但要证明它是噪声主因，需要相同数据、训练配置和预算下的归一化对照。

## 对修复建议的审核

- 先做同一当前 rtc35 checkpoint、同一组观测/seed 的 baseline/零噪声/时间平滑噪声/后缀平滑比较是合理的。要补上**真实规划前缀**条件；原 evaluate.py 的 self_prefix 来自上一轮模型预测，不等于当前执行规划器的前缀。
- 零噪声、平滑噪声改变训练时独立高斯噪声的分布；平滑后恢复单位方差也不能恢复时间独立性。必须检查 heldout 动作/夹爪误差、边界速度、纠偏/制动延迟，不能仅凭曲线漂亮上线。
- 现有前缀模式样本数不同（例如旧 oracle 24 对、self 12 对），模式间准确度比较必须取相同观测子集。只有 2 个留出 episode，不能把帧/seed 当更多独立任务。
- **逐步统计 [50,14]** 需要重算、重训练及完整往返契约更新。目前 Normalize 只切最后一维，6/7/8 行前缀不能直接和 50×14 统计广播；前缀需按新 chunk 时间位置切统计。服务器旧前缀模式保留夹爪 normalized 值的逻辑也须随时间相关统计重新审计。不能只替换 norm_stats.json。
- 预测相邻步增量再累计是另一种动作契约，会引入积分误差累积，需要训练、RTC 编解码、输出还原一起改；不是现有绝对轨迹的后处理开关。
- 当前训练 delay weights 为 `[35,2,3,4,6,20,12,3,10,3,2]`，0–10 都覆盖。优先补 d=0/4/5/6/7/8/10 的真实前缀与规划前缀评测，避免仅凭 d=0 的 loss 选择模型。
